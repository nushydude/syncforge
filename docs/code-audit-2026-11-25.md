### AUD-001 — Copy staging unconditionally deletes an existing sibling

**Sync writes / filesystem integrity, maintainability. High, high confidence, S.** Manual, watch and scheduler dispatch copies to `safe_copy_file` (`src-tauri/src/engine.rs:938–965`). The staging name is a deterministic sibling with `.syncforge.tmp` suffix (45,123–126). If it already exists the real file is removed before copy, verification or commit. On error the code cleans the same path (191–214). A legitimate sibling is permanently removed even when Recycle Bin is enabled and if the subsequent copy fails. Existing tests cover clean stage and replacement (1062–1097). [src-tauri/src/engine.rs](../src-tauri/src/engine.rs#L938)

**Planning and acceptance.** Create uniquely and exclusively owned sibling stages and clean up only owned files. Generated-fixture checks preserve a sentinel sibling on success and injected failure, remove stages owned by the failed operation, preserve ordinary files during abandoned-stage recovery, maintain verification, and preserve existing destination bytes on failed commit. Scope non-Windows copy fallback (183–187) separately because injected replacement failures are needed to establish its integrity.

### AUD-015 — Existing pair drafts can execute with overlapping roots

**Pair editor and all execution paths / filesystem integrity, validation. High, high confidence for ordinary nested roots, M.** An existing pair's Run sync button passes the unsaved `editing` object directly and bypasses form submit/save validation (`src/components/pairs/PairEditor.tsx:117–121,372–394`). Text equality and nesting checks are confined to pair save (`src-tauri/src/commands/pairs.rs:13–28,53–60`), while `run_pair` accepts the draft by ID (`src-tauri/src/commands/run.rs:53–103`). Engine resolves and scans both roots without checking equality or nesting (`src-tauri/src/engine.rs:297–328,406–439`). Work admission canonicalizes paths to compare writers against existing requests but does not compare the two roots of the same request (`src-tauri/src/state.rs:242–255,350–361`). When a draft Echo source lies inside its destination, the destination scan can include the physical source subtree as right-only. The planner can emit a tree delete there (`src-tauri/src/diff.rs:171–173`, `engine.rs:218–235,971–974`). The manual Recycle Bin setting affects recoverability, and source removal is outside intended scope either way. No alias or adversarial filesystem setup is necessary. **Planning and acceptance.** Check the resolved roots at the shared backend before any planning or writes, including manual preview/run, automatic plans, stale/legacy stored configurations and current draft roots. Return an actionable pair validation error and preserve safe draft preview/run if allowed by product policy. Regression checks cover both nesting orders and equality for existing-pair drafts/legacy data without performing an unsafe delete. Host-specific link, junction, remount and root-identity race coverage remains H1. This finding concerns root topology. AUD-003 covers relative-name identity.

### AUD-002 — Echo directory deletes operate beyond include/exclude filters

**Scanner/planner/engine / filesystem integrity, cross-layer contracts. High, high confidence, M.** A right-only parent can match a filter while a child is excluded. Scanner omits the child without warning (`src-tauri/src/scanner.rs:252–266,289–309`) and initial incomplete-scan safeguards remain active (65–85). `plan_echo` emits parent deletion (`src-tauri/src/diff.rs:149–173`) and can collapse descendant actions (487–510). Engine removes the physical tree (`src-tauri/src/engine.rs:218–235,966–974`). Fresh manual run has no cached preconditions (`src-tauri/src/commands/run.rs:69–82`, `engine.rs:406–439,517–532`). Applicable manual settings allow permanent deletion. Watch and scheduler supply a plan without preconditions and always request Recycle Bin semantics (`src-tauri/src/run_coordinator.rs:193–225,306–330`). Recycling still removes protected data from its location. Cached preview can instead reject because its subtree walk sees the excluded descendant as unexpected (`engine.rs:763–842`). [src-tauri/src/scanner.rs](../src-tauri/src/scanner.rs#L252) · [src-tauri/src/diff.rs](../src-tauri/src/diff.rs#L149) · [src-tauri/src/engine.rs](../src-tauri/src/engine.rs#L218) · [src-tauri/src/commands/run.rs](../src-tauri/src/commands/run.rs#L69)

**Planning and acceptance.** Use one filter/descendant contract for all run modes and keep the incomplete-scan guard. Execute eligible leaf deletions and retain parents containing excluded, unknown or protected content unless another approach proves complete eligible membership with equivalent safety. Distinguish blocked parent from eligible work in preview/history. Tests cover include/exclude, mixed descendants, partial scans, a member added after planning and all execution paths.

### AUD-006 — Reviewed intent can be recomputed or incompletely validated

**Queue/cache/engine / safety, state contracts. A later no-plan run can include undisplayed Echo deletions or apply path-keyed conflict choices to newly observed versions. Ask follows a separate route that generates a new pre-run plan even after an earlier manual preview (`src/store/runStore.ts:410–463,528–535`). When that plan's handle expires after presenting choices, those choices can reach the fallback. Saved edits/deletes while the same run is pending are UI-guarded.

A still-cached plan checks only the target and any target subtree for `DeleteLeft` or `DeleteRight` (`src-tauri/src/engine.rs:449–473,517–538,763–775`). It never validates evidence on the other side, such as continued absence. Fresh and background plans bypass the cached precondition index. Watch and schedule request Recycle Bin semantics (`src-tauri/src/run_coordinator.rs:213–219,319–325`). Cached copy validates both sides. [src/store/runStore.ts](../src/store/runStore.ts#L295) · [src-tauri/src/state.rs](../src-tauri/src/state.rs#L19) · [src/store/pairsStore.ts](../src/store/pairsStore.ts#L439) · [src/components/pairs/PairEditor.tsx](../src/components/pairs/PairEditor.tsx#L372)

**Planning and acceptance.** Distinguish deliberate fresh-run intent at confirmation from review of a fixed plan and make destructive plan drift visible. Require updated approval after scope/relevant versions change, bind choices to the reviewed versions, and verify all evidence driving destructive actions across modes. Factor validated root/subtree/name rules in AUD-015/002/003 and define how AUD-004's baseline revision binds to decisions. Test fake expiry, eviction, edited drafts, Ask choices, source reappearance, intentional fresh run and an unattended skip/replan outcome.

### AUD-009 — Duplicate job updates can revert and results lack bounds

**Duplicate scan, SQLite, IPC and view / state correctness, scalability. Medium, high confidence, M–L.** SQLite persists complete result JSON with no observed retention (`src-tauri/src/persistence.rs:270–290,379–425,460–490,927–939`).
